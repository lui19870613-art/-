==========================================
（他の担当者・別のClaudeセッションが、この文書だけを読んで

最終更新日：2026年9月29日


==========================================
第0章：これは何か
==========================================

楽天市場のランキングバナー（PSDファイル）には、「○月○日 更新」という
日付つきの文字（帯・カードの中）が複数入っている。この日付部分を、
決まった書式・見た目にそろえて直し、複数のバナーを縦につなげた
「合成データ（001-002など）」の該当部分に差し替え、最終的なJPEG画像
として書き出す作業。

この文書は、その作業を初めて行う人（別のClaudeセッション）が、
これまでの担当者と同じルールで、同じ結果を出せるようにするための
マスタープロンプト兼手順書である。

依頼する側（人間）は、次のような短い日本語で指示してくる：

  「【フォルダのパス】
   このフォルダ内の001で終わるデータをこれまで同様に全て編集し、
   001-002のデータの同じ部分に差し替えて、最終jpegに書き出して」

  「@ファイルパス これも同様に」

  「文字サイズは○○にして」「日付を○px上（下・左・右）へ」

  「メダルを、リアルタイム○個・デイリー○個にして」

これらの短い指示だけで、以下に書く「標準仕様」を過不足なく実行できる
ようにしておくことが、この文書の目的である。


==========================================
第1章：絶対に守る大原則
==========================================

1-1. 元ファイルは絶対に上書きしない
------------------------------------
- 依頼された元のPSD（例：kk_ranking_xxx_001.psd）は、絶対に上書き
  保存しない。
- 必ず「同じフォルダ」に、「ファイル名の末尾に今日の日付6桁を
  (YYMMDD) の形で付けた」新しいファイルとして保存する。
    例：kk_ranking_xxx_001.psd
     → kk_ranking_xxx_001(260929).psd
- すでに (YYMMDD) が付いているファイルを元に作業する場合は、
  古い日付部分を取り除いてから、今日の日付を付け直す。
    例：kk_ranking_xxx_001(260920).psd
     → kk_ranking_xxx_001(260929).psd
- 保存先に同名ファイルがすでに存在する場合は、上書きせずスキップし、
  「すでに存在します」と報告する（同じ日に同じファイルを2回処理
  しようとした場合の事故防止）。

1-2. 保存前に、開いているファイル名を必ず確認する
------------------------------------------------
★これは、実際に人間の元ファイルを誤って上書きしてしまった重大事故を
  受けて追加された、最重要ルールである。★

- Photoshopは、フリーズや多数のファイルを開閉する作業のあとで、
  「アクティブなドキュメント」が意図しないファイルにすり替わる
  ことがある（原因不明の場合もある）。
- そのため、PSDを保存する直前には、必ず次のように
  「今アクティブなドキュメントの名前」が「保存したいファイル名」と
  一致するかをスクリプト内でチェックしてから保存する。
  一致しなければ、絶対に保存せず、エラーとして処理を止める。

  例（ExtendScript）：
  ```
  var doc = app.activeDocument, expect = "期待するファイル名.psd";
  if (doc.name != expect) {
    "ABORT: active doc is '" + doc.name + "', expected '" + expect + "'";
  } else {
    var so = new PhotoshopSaveOptions();
    so.layers = true; so.embedColorProfile = true;
    doc.saveAs(doc.fullName, so, false, Extension.LOWERCASE);
  }
  ```
- JPEG書き出し時も同様に、ファイル名チェックをしてから書き出す。
- 複数ファイルを連続処理するときは、1ファイルごとに
  「開いているドキュメントをすべて閉じる」→「目的のファイルだけを
  開く」→「ドキュメント数が1で、名前が正しいことを確認する」
  という手順を必ず踏んでから編集・保存に入る。

1-3. Photoshopが反応しなくなったら
------------------------------------
- 大量の操作の後や、長時間の作業の後、Photoshopへの命令
  （AppleScript経由のdo javascript）が固まる／タイムアウトする
  ことがある。
- その場合は、無理に連続でコマンドを送らず、一定間隔で
  「app.documents.length」など軽いコマンドが通るかを確認しながら
  復帰を待つ。
- 復帰したら、必ず「今開いているドキュメントの一覧」を確認し、
  意図しないファイルが残っていないか、意図したファイルの
  保存状態（saved/unsavedと内容）が正しいかを再確認してから
  作業を再開する。過去の状態を「たぶんこうなっているはず」と
  推測で信用しない。実際にスクリプトで確認する。


==========================================
第2章：日付文字の書式ルール
==========================================

対象：「○○更新」を含む文字レイヤー（「集計期間」は対象外）

2-1. 基本の2行フォーマット
------------------------------------
【時刻ありの場合＝リアルタイムランキング】
  1行目：リアルタイムランキング
  2行目：2019年3月5日(火) 09:25更新

【時刻なしの場合＝デイリーランキング】
  1行目：デイリーランキング
  2行目：2019年3月4日(月)更新 (集計日：3月3日)

- 曜日は、実際のカレンダー計算で正しく出す（決め打ちしない）。
- デイリーの「集計日」は、更新日の前日。
- 秒は表示しない（「09:25:00」ではなく「09:25」）。
- 元のテキストが「2019/3/5 09:25:00更新」のような生の日時表記でも、
  正規表現で日付・時刻を抜き出して、上記の標準書式に組み立て直す。
- 元のテキストが「2023/12/24 23:20:00」のように「更新」の文字が
  欠けている（壊れている）場合でも、末尾が「...更新」のパターンに
  近い、または日時らしき文字列であれば、日付データとして拾って
  変換対象にする（後述「隠れた/壊れた日付レイヤー」を参照）。
- 「集計期間」を含む文字は、絶対に日付レイヤーとして扱わない
  （書式変換の対象外。別ルールで扱う＝第6章）。

2-2. フォント・色
------------------------------------
- フォント：小塚ゴシック Pr6N Bold（KozGoPr6N-Bold）
  ※本物のBoldを使う。「擬似ボールド（fauxBold）」は必ずOFFにする。
- 色：#000000（黒）
- 行間：自動（useAutoLeading = true）、段落前アキ（spaceBefore）は0。
  2行目が1行目に重ならないようにする。

2-3. 位置の基本ルール
------------------------------------
- 元のテキストの左上位置（x, y）は、書式変換だけでは動かさない
  （文字を書き換えても位置がズレないよう、変換前の左上座標を
  記録しておき、変換後に同じ座標へ戻す）。
- 日付レイヤーは、常にそのレイヤーグループ内で最前面に移動する
  （ただし、幅1200px超のワイドな合成キャンバスでは、最前面移動は
  行わない＝後述4-5）。
- 標準の追加調整として、日付テキストは元の位置から「上に8px」
  動かす（見やすさのための標準調整。y座標を-8する）。

2-4. 日付とほかの画像とのリンクを外す（重要・毎回必須）
------------------------------------
- 一部のバナーでは、日付の文字レイヤーが、背景のカード画像や
  トロフィー画像と「リンク」されている場合がある。リンクされた
  ままレイヤーを動かすと、リンクされた画像まで一緒に動いてしまい、
  デザインが崩れる。
- そのため、日付レイヤーの位置を動かす**前に**、必ずそのレイヤーの
  リンクを解除する（ExtendScriptで layer.unlink() を呼ぶ）。
  これは全ファイル・毎回、例外なく行う。
- リンク解除の副作用が心配なので、位置調整が終わったあと、
  日付以外のレイヤー（画像類）の位置が元ファイルと変わっていないか
  を確認する（可能であれば、元ファイルと座標を比較する）。


==========================================
第3章：文字サイズ・レイヤー効果のルール
==========================================

3-1. 文字サイズの決め方
------------------------------------
日付の「数」と、帯（カード）どうしの「間隔（重なり具合）」を見て、
以下を目安に選ぶ。数値は絶対ではなく、実際にプレビューして
「隣の日付と文字が重ならないか」「枠からはみ出さないか」を
必ず目視確認してから決定する。

  日付が 1〜4か所　　　　　→ サイズ 13
  日付が 5〜11か所　　　　　→ サイズ 11〜12
  日付が 12〜20か所　　　　 → サイズ 10
  日付が 21〜30か所（帯が
    かなり重なっている場合）→ サイズ 9〜10
  デイリー表記（2行が長い）
    がさらに重なる場合　　　→ サイズ 8〜9まで下げる

- 「見やすく」とだけ依頼された場合も、まずはサイズを大きくする
  方向で試し、重なりが出たら1段階ずつ下げて調整する。
- サイズを変えたあとは、必ず「位置合わせ（第4章）」をやり直す
  （translateで位置がズレるため）。

3-2. レイヤー効果（縁取り・光彩）
------------------------------------
- 既存の縁取り（フチ）が付いている場合は、そのまま活かす
  （太さ・色を変えない）。
- 縁取りが付いていない場合は、新規に付ける：
    白フチ（Stroke）：外側、2px、白、不透明度100%
- 背景の画像やショップ名の文字と重なって読みにくい場合は、
  さらに「白い光彩（Outer Glow）」を追加する：
    広がり（Choke）：1px、ぼかし（Size）：2px、白、不透明度100%
- 縁取りを太くしすぎたり、光彩を強くしすぎたりすると、日付どうしが
  近い場合に「にじんで」重なって見えることがあるので注意する。
  サイズを大きくする代わりに効果を強くする、という調整も可。


==========================================
第4章：位置調整（枠内に収める）のルール
==========================================

4-1. 「枠（帯／カード）」の考え方
------------------------------------
- 多くのバナーは、白い商品カード画像（オレンジ色の縁取りがある
  ことが多い）が、斜めに何枚も重なって並ぶデザインになっている。
- 日付の文字は、この「カードの中」に収まっていなければならない。
  枠からのはみ出し・隣のカードへの越境はNG。

4-2. カードの自動判定
------------------------------------
- 通常レイヤー（LayerKind.NORMAL）のうち、
    幅：150px 〜 1120px
    高さ：300px未満
  の範囲に収まるものを「カード候補」として扱う。
- より厳密に絞り込みたい場合（カードのサイズが分かっている場合）は、
  実際のカードの幅・高さに近い範囲（例：330〜370px幅、
  70〜100px高さ）で絞り込むと精度が上がる。

4-3. 日付をカード内に収める処理
------------------------------------
- 各日付テキストについて、最も重なり面積が大きいカードを
  「そのテキストが属するカード」とみなす。
- テキストの右端・下端・左端・上端が、カードの内側から
  「余白5px」を切るように、はみ出した分だけ平行移動する
  （文字サイズやフォントは変えない、位置だけ動かす）。
- 対応するカードが見つからない日付は、非表示にする
  （削除はしない）。該当があれば必ず報告する。

4-4. ショップ名などとの重なりを避ける
------------------------------------
- 「セレクトショップKK」「39ショップ」などの固定テキストに、
  日付が重なって読めなくなる場合は、日付をカード内の右側
  （空いているスペース）へ寄せる。
- 右に寄せる際も、4-3のカード内クランプは必ず再度かける
  （はみ出し防止）。

4-5. 幅の広い合成キャンバス（ワイド）の例外
------------------------------------
- キャンバス幅が1200pxを超えるような、横に長い合成画像の場合は、
  日付レイヤーの「最前面への移動」は行わない（元のレイヤー順を保つ）。
  理由：ワイド合成では、最前面移動がデザインの重なり順を崩す
  ことがあるため。

4-6. カードの数と日付の数が合わない場合（隠れた/壊れた日付レイヤー）
------------------------------------------------------------
- カードの数（例：30枚）に対して、正しく変換できた日付の数が
  少ない（例：29個）ことがある。これは、元データの中に
  「更新」の文字が欠けている、または表示が非表示（vis=false）に
  なっている、壊れた・隠れた日付テキストが混ざっていることが原因。
- そのようなレイヤーを見つけたら：
   1. 内容（生の日時）を確認し、標準の書式（2-1）に変換する。
   2. フォント・色・サイズ・効果を他の日付と統一する。
   3. 表示状態をON（visible=true）にする。
   4. どのカードに対応するのかを特定する
      （下記の「空きカードの探し方」を参照）。
   5. そのカードの位置に合わせて、テキストの位置を調整する。

  【空きカードの探し方（重なりが激しく自動判定が効かない場合）】
   - 同じ列（同じ斜めの並び）にあるカードを、上端のY座標が
     小さい順（＝手前）にソートする。
   - 同じ列にある、既存の正しい日付テキストも、Y座標順にソートする。
   - カードの枚数のほうが日付の数より1つ多いはずなので、
     カード枚数から日付の数を引いた分だけ、対応が一つズレている
     箇所がある。「カードの上端Ｙ＋一定のオフセット」で計算した
     予測位置と、実際の日付Ｙ座標を突き合わせ、オフセットの
     パターンが崩れる箇所（＝空きカード）を特定する。
   - 特定したら、壊れていた日付テキストを、その空きカードの
     「上端Ｙ＋オフセット」「左端Ｘ＋オフセット」に配置する。
     オフセットの値は、同じ列の他の（正しく配置されている）
     日付テキストとカードの位置関係から逆算する
     （例：カード上端+62px、カード左端+69px、など列ごとに実測）。
   - 一度配置したら、必ず同じ列の全テキストを「カード上端の
     昇順」と「日付Ｙ座標の昇順」で1対1に機械的に再配置し直す
     （手動の微調整だけだと、隣との間隔がバラバラになりやすい。
     全部を計算し直して揃えるほうが確実で速い）。
   - 最後に、拡大した画像プレビューで、実際に重なりがないか、
     左右の列と同じような間隔になっているかを必ず目視確認する。


==========================================
第5章：段落スタイルの技術的な注意点（ExtendScript特有の癖）
==========================================

- テキストの内容（contents）を書き換えると、Photoshopが
  段落スタイル（行間・段落前アキ）を勝手にリセットすることがあり、
  2行が重なって見えることがある。
- 対策：内容を書き換えたあとに、必ず paragraphStyleRange に対して
  spaceBefore=0、leadingType=leadingBelow を明示的に再設定し、
  useAutoLeading=true にする。
- 1行にまとめる場合（第9章参照）は、この段落設定はシンプルに
  そのまま1レンジに対して適用すればよい。


==========================================
第6章：右下の「集計期間」表示のルール
==========================================

- 「集計期間：○年○月○日～○年○月○日」という文字レイヤーが
  ある場合、これは日付レイヤーとして書式変換の対象にはしないが、
  以下の内容に必ず更新する：

    集計期間：（すべての日付の中で最も古い日付）
             ～（すべての日付の中で最も新しい日付）

- 全ての日付テキストから年月日を抽出し、最小・最大を計算して、
  「○年○月○日」の形式（西暦4桁・月日はゼロ埋めなし）で当てはめる。
- すでに正しい内容になっている場合は、変更不要（「変更なし」と
  ログに残す）。


==========================================
第7章：合成データ（001-002など）への差し替えルール
==========================================

7-1. 基本の考え方
------------------------------------
- 「001-002」「001-002-003」のような、複数枚のバナーを縦に
  つなげた合成PSDがある。この中の「1枚目（001に相当する部分）」
  だけを、編集済みの新しいバナーに差し替える。
- 2枚目以降（メダル一覧、お客様の声、合成キャンバスなど）は、
  絶対に触らない。

7-2. 差し替えの手順
------------------------------------
 1. 編集済みの001 PSDを、JPEG（画質12、カラープロファイル埋め込み、
    ベースライン標準、マット無し）で書き出す。
 2. 合成PSD（001-002など）を開く。
 3. 一番上（Y座標が最小＝0付近）にある、幅600px以上の画像レイヤー
    を「差し替え対象」として自動検出する
    （複数レイヤーがある場合、Y座標が最も小さいものを選ぶ）。
 4. 対象レイヤーの種類によって差し替え方法を分ける：
    - スマートオブジェクトの場合：
        「コンテンツを置き換え」（placedLayerReplaceContents）で、
        手順1のJPEGに差し替える。位置・サイズは自動的に維持される。
    - 通常レイヤー（貼り付け画像）の場合：
        手順1のJPEGを開いて全選択・コピーし、対象レイヤーを選択した
        状態でペーストし、新しいレイヤーを元のレイヤーの位置
        （通常は左上0,0）にぴったり合わせてから、古いレイヤーを
        削除する。
 5. 差し替えた画像は、キャンバス上端にぴったり合わせる
    （上に余白ができないようにする。translateでY座標を0に補正）。
 6. 合成PSDを、末尾に今日の日付を付けた新しいファイル名で保存する
    （元の合成PSDも上書きしない）。
 7. 同じ内容でJPEGも書き出す（画質12）。これが「最終jpeg」。

7-3. 差し替え時の確認事項
------------------------------------
- 合成後のプレビュー画像を必ず目視確認し、
    - 上（差し替えた部分）が編集後の内容になっているか
    - 下（メダル・お客様の声など）が元のまま変わっていないか
  を確認してから報告する。


==========================================
第8章：ファイル出力の一覧（最終成果物）
==========================================

各案件フォルダに、以下のファイルが作られる想定：

  1. 編集済み単体001
     　例：kk_ranking_xxx_001(260929).psd
     　例：kk_ranking_xxx_001(260929).jpg
  2. 差し替え後の合成データ（★最終成果物★）
     　例：xxx_001-002(260929).psd
     　例：xxx_001-002(260929).jpg　←依頼文の「最終jpeg」はこれ

- 元ファイル（日付サフィックスなしのもの）は、どちらも一切
  変更しない。


==========================================
第9章：デザイン上の例外対応（重なりがどうしても解消しない場合）
==========================================

- 帯（カード）が非常に多く重なっている（20〜30枚以上）デザインで、
  標準の「見出し1行＋日付1行」の2行フォーマットのままだと、
  カード1枚あたりの表示できる高さ（斜めのステップ幅、例えば
  18〜20px程度）よりも、文字の高さ（2行で26〜27px程度）の方が
  大きく、どうしても隣の行と重なってしまうケースがある。

- その場合の例外対応：
    見出しと日付を、改行せず「スペース区切りで1行」にまとめる。
      例：「リアルタイムランキング 2024年2月10日(土) 03:53更新」
    これにより、1行分の高さ（13〜15px程度）に収まり、
    カードの段差の中に重ならず収まるようになる。
- この例外処理を行った場合は、報告時に「このファイルは重なりが
  避けられないデザインだったため、1行フォーマットに変更した」旨を
  必ず明記する（標準は2行フォーマットであることを担当者が
  忘れないように）。
- 例外処理後も、第4章の「カード内に収める」処理は必ず行う。


==========================================
第10章：メダル（1位バッジ／○冠獲得）の修正ルール
==========================================

- 「メダルの数をバナーの日付数に合わせて」と言われた場合：
    バナー本体の日付の数と、獲得メダルの表示数・「○冠獲得！」の
    数字を一致させる。
- 「メダルのうち○個をデイリーにして」と言われた場合：
    指定された個数のメダルの文字を「リアルタイムランキング」から
    「デイリーランキング」に書き換える。順番の指定がなければ、
    参考にできる別ファイルの並び順に合わせるか、先頭から順に
    変更し、その旨を報告する。
- 「4冠のままでOK」のように、数・大きさは変えず文字だけを
  他ファイルと同じ内容にそろえる依頼もある。その場合は、メダルの
  個数・デザインサイズを変更せず、文字の内容・フォント・サイズ・
  段落設定だけを、参照元と同じにする。
- 文字を書き換えたときは、第5章の段落スタイルの注意点と同様、
  行間・中央揃えなどを他のメダルと同じ設定に必ずそろえる
  （書き換えた1個だけ見た目が崩れやすいので要注意）。


==========================================
第11章：ショップ名など、通常は変更しない項目
==========================================

- ショップ名（例：「DCT COMPANY」への変更）は、明確に依頼された
  場合のみ行う。デフォルトでは絶対に変更しない。
- 商品名・カテゴリ名・価格などの文言は、明示的な依頼がない限り
  変更しない。


==========================================
第12章：フォルダ・ファイル名が作業中に変わる問題への対応
==========================================

- 作業対象のフォルダやファイルは、担当者（人間）の作業と並行して、
  リネーム・移動されることがある（例：「名称未設定フォルダ」→
  「10000775」、末尾に「(KK)」が付く、など）。
- 保存先を指定したパスが「存在しない」エラーになった場合は、
  慌てずに、ファイル名（拡張子より前の部分）で同じDesktop/
  Downloads以下を検索し、移動先の新しいパスを特定してから
  作業を続ける。
- 見つけた際は、「フォルダ名が変わっていたので、新しい場所で
  作業しました」と一言報告する。


==========================================
第13章：基本の作業フロー（ステップ・バイ・ステップまとめ）
==========================================

対象ファイル1つにつき、以下の順番で行う：

  0. Photoshopで開いているドキュメントを、いったんすべて閉じる。
  1. 対象の元PSDを開く。ドキュメント数が1、名前が正しいことを
     確認する。
  2. すべての日付レイヤーを検出し、書式を第2章のルールで変換する
     （フォント・色・段落設定も同時に適用）。
  3. 日付レイヤーのリンクを解除する（第2-4節、必須）。
  4. 元の左上座標に位置を戻し、さらに標準8px上へ移動する。
  5. 日付の数・重なり具合を見て、文字サイズを決める（第3章）。
     サイズ変更後は再度、位置をカード内に収め直す。
  6. レイヤー効果（縁取り・光彩）を付ける（第3-2節）。
  7. 日付をカード内に収める（第4章）。ショップ名との重なりが
     あれば、さらに位置を右に寄せて再クランプする。
  8. 「集計期間」があれば、最初と最後の日付に更新する（第6章）。
  9. カードの数と日付の数が合わない場合は、第4-6節の手順で
     壊れた/隠れたレイヤーを探して復元する。
 10. 仕上がりをプレビュー（PNG書き出し等）で拡大確認し、
     重なり・はみ出しがないかチェックする。
     問題があれば、5〜9を繰り返す。
 11. 保存直前に、ファイル名チェック（第1-2節）を行ってから、
     今日の日付を付けた新しいファイル名でPSD保存する。
 12. 同じ内容でJPEG（画質12）を書き出す。
 13. 001-002などの合成データがあれば、第7章の手順で差し替え、
     新しい日付付きのPSD・JPEGとして保存する。
 14. 結果（変換した日付数、リアルタイム/デイリーの内訳、
     使用した文字サイズ、特記事項）を日本語で簡潔に報告する。


==========================================
第14章：報告のしかた（担当者への伝え方の型）
==========================================

作業完了後の報告は、次の要素を簡潔にまとめる：

  - 保存したファイル名（PSD/JPEGそれぞれ、フルパスではなく
    ファイル名で分かりやすく）
  - 元ファイルは変更していない旨
  - 日付の数（内訳：リアルタイム○件・デイリー○件）
  - 使用した文字サイズと、選んだ理由（重なりを避けるため、等）
  - 集計期間を変更したかどうか
  - 合成データへの差し替え内容（何を差し替え、何を変えていないか）
  - 気になる点・目視で気づいた軽微な重なりやはみ出し（あれば）
  - フォルダ名の変更など、イレギュラー対応をした場合はその旨

過度に長い専門的な説明は避け、依頼者（非エンジニア）が読んで
すぐに状況を把握できる、簡潔な日本語で書く。


==========================================
第15章：やってはいけないこと（禁止事項まとめ）
==========================================

  × 元ファイル（日付サフィックスなしのオリジナル）を上書きする
  × ファイル名を確認せずに保存する
  × 日付レイヤーのリンクを外さずに位置を動かす
  × 依頼されていないのに、ショップ名・商品名・価格などを変更する
  × 対応するカードが見つからない日付テキストを削除する
    （非表示にするだけにとどめる）
  × 合成データの2枚目以降（差し替え対象外の部分）を変更する
  × 重なりが残ったまま「完了」と報告する
    （必ず目視でプレビュー確認してから報告する）
  × Photoshopの状態を推測で判断する
    （必ずスクリプトで実際の状態を確認する）


==========================================
付録：よく使うExtendScriptの技術メモ
==========================================

- レイヤーの実ピクセルサイズ：
    Math.round(layer.bounds[n].as("px"))
- テキストの実際の表示サイズ（ラスタライズ後の見た目サイズ）は、
    raw_size（layer.textItem.size） × transform.yy（k値）
  で決まる場合がある（レイヤーが縮小・拡大されている場合）。
  表示サイズをNptにしたい場合は、素直に
    layer.textItem.size = new UnitValue(N, "pt")
  と設定すれば、Photoshopが自動でk値を考慮して正しい表示サイズに
  してくれる（自分でk値を逆算する必要は通常ない）。
- テキスト内容の変更で段落設定が崩れる問題への対処は第5章参照。
- JPEG書き出し設定：
    quality = 12、embedColorProfile = true、
    formatOptions = FormatOptions.STANDARDBASELINE、
    matte = MatteType.NONE
- PSD保存設定：
    layers = true、embedColorProfile = true

以上。
